# Build 27 — setup replay, model coverage, and delivery feedback

Reviewed 2026-09-06 on macOS 26.6.1, M5 Max, 48 GB. This is development-build evidence, not a release certification.

## Changes

- **Practice replay.** The setup illustration temporarily yields to actual recording/processing, reveals the completed transcript with a restrained glow, then resumes its lesson using the latest successful practice text. Keycaps have a spring press/release and visible depth. Stage transitions crossfade; the labelled replay types at about 28 characters per second. Ordinary dictation does not receive artificial typing. A cancelled subsequent test keeps the prior successful replay, labelled “Your last test · No recording.” Long results remain available in a disclosure. Reduce Motion removes animated motion and the typing sequence.
- **Download feedback.** The existing shared queue now publishes preparation, transfer, and checking phases, actual bytes received, sampled transfer rate, and the last data timestamp. The onboarding shelf keeps progress visible across sections. A transfer with no new data for eight seconds shows its wait duration instead of implying progress. Checking/preparation retain an indeterminate activity indicator. UI transfer updates are throttled to approximately 10 Hz; wait labels update once a second. Per-file identity rejects stale callbacks. Downloads still stop on an actual failure/cancel, keep completed files, and use temporary staging.
- **Model coverage.** Moonshine Tiny/Base and Granite now have their official publisher avatars. Whisper Base, Whisper Small, and Moonshine Base show a neutral “Not ranked” badge because the current comparable HF dataset has no row for those checkpoints. Their Details explain this, rather than implying a measured zero or substituting another model’s score. See [sources and rating scope](MODEL-VISUAL-COVERAGE-2026-09-06.md).
- **Shortcut checks.** Settings, the binding editor, and setup expose exact known conflicts. Checks refresh on application activation, editor opening, and saving; there is no per-keystroke polling or hotkey takeover. Existing bindings are preserved. The detector reads enabled macOS symbolic hotkeys and a supported legacy Raycast launcher setting. Raycast 2’s private settings and other unenumerable bindings remain explicit coverage gaps. See [research and limits](SHORTCUT-CONFLICTS-2026-09-06.md).
- **Prompt HUD dismissal.** A successful paste dispatch starts a 200 ms completion hold. Readback can subsequently mark it confirmed without reopening the HUD or resetting its dismissal timer. No-dispatch failures still show a warning. Transcript-only results have a 600 ms success hold. Fields without readable source text/selection, and no-op replacements, return unconfirmed immediately after dispatch: they cannot benefit from the previous one-second readback loop. Readable, changed targets retain the bounded verification loop and conditional clipboard restore.

## Limits

- “Not ranked” is intentional until comparable upstream data exists; it is not a low quality rating. No new ASR quality or speed benchmark was run, and no model weights were downloaded for this pass.
- Shortcut detection is bounded. In particular, having Raycast installed does not establish that it uses Option–Space. Legacy v1 parsing has fixture coverage, not a live v1 installation test.
- A readable editor that delays its AX acknowledgement can still keep the current insertion transaction busy for up to one second after dispatch. This retains existing serialization and clipboard ownership; the HUD no longer adds its own two-second wait. An opaque editor no longer incurs that useless delay.
- The native download-state review uses the shipping presentation with isolated fixture values; the tiny HTTP harness exercises the real queue. Neither is a multi-gigabyte slow-network endurance test.
- Preferences, vocabulary, modes, and model downloads were preserved. Session-only history resets on relaunch. No GitHub publication was performed; that remains pending the user’s explicit readiness instruction.
