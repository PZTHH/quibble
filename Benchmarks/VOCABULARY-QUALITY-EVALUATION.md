# Preferred-word vocabulary: qualification results

Evaluated: 2026-09-05. This supersedes the quality conclusion of the first build-7 CPU slice.

> Build 8 update: a guarded Whisper audio helper is now integrated. See [implementation, new measurements and remaining misses](VOCABULARY-AUDIO-BUILD-8.md). The recommendations below record the earlier experiment stage.

## Earlier decision

**The uncommon-name requirement is not yet delivered.** The visual vocabulary editor, approved literal corrections, migration safeguards, and cleanup spelling checks work as implemented; their tests do not establish that adding an arbitrary preferred name makes recognition reliable.

Do not enable an unconditional fuzzy matcher, a dictionary prefix stripped after S1, or a general text rewriter as the universal solution. The experiments below all exposed either missed names or unwanted changes. Keep the ordinary app's inference behavior until a replacement passes qualification. ASR-side phrase biasing is the next engineering direction because it uses acoustic evidence and adds no neural model, but the greedy prototypes do not yet qualify.

The next bounded implementation experiment should retain competing speech hypotheses (small-beam decoding or candidate-versus-original acoustic rescoring), with phrase-completion scoring and explicit unfinished-phrase penalties. Test it against the same negatives and an independent human-recorded holdout before selecting defaults. This is a proposed next step, not a proven fix or a promise that beam search will solve the problem.

## What was tested

All tests were local. Native ASR runs explicitly denied network. Text fixtures were manually constructed. Audio was generated by macOS Samantha using English respellings such as Shivawn and Keeva; it is a reproducible engineering probe, **not a human pronunciation benchmark**. No live competitor binaries were benchmarked. The user's exact uncommon name and recognition output have not been provided.

- `vocabulary-uncommon-names.json`: four preferred-word-only examples, three CPU runs each. Current matcher failed all 12; its same-prefix/edit-distance filter cannot handle names such as Siobhan/“Shivon.”
- `vocabulary-name-evaluation.json`: 18 text cases, nine intended corrections and nine controls. Controls include unrelated names, ordinary homophones, brands used as common words, and a dictated instruction that must remain text.
- `competitor-probes/handy-additional-fixtures.json`: 24 additional text cases, twelve name corrections and twelve controls.
- `vocabulary-name-audio.json`: seven positive and six negative audio cases, with all thirteen saved words supplied together. Two runs per configuration.

## S1 prefix suggestion

Tested the publisher's normal S1 prompt with a baseline and eight dictionary-prefix layouts: bare list, names/terms reference, reference sentence, brackets, vocabulary/transcript headings, correct-spellings heading, repetition, and conversational introduction. There were 162 calls across 18 fixtures.

| Layout | Expected text after screening / 18 |
|---|---:|
| No prefix | 10 |
| Bare list | 9 |
| Names/terms reference | 10 |
| Reference sentence | 10 |
| Brackets | 12 |
| Vocabulary + transcript headings | 12 |
| Correct-spellings heading | 9 |
| Repeated spellings | 8 |
| Conversational introduction | 10 |

The heading/bracket variants produced useful individual name corrections. They did not provide a dependable way to separate the dictionary from the dictated text. For example, the vocabulary-heading variant sometimes returned only “Vocabulary: QuickTime.” and dropped the sentence. Another format merged a prefixed name into the actual sentence without correcting the intended name. One repetition call reached the generation limit.

These counts use an **optimistic screening step**: remove the exact prefix when it remains intact; otherwise compare the raw output. They are not evidence of a robust extraction algorithm. Median whole-call times were approximately 0.37–0.41 seconds, including loading a scoped model for this harness. No prefix variant was added to normal dictation.

Evidence: `results/vocabulary-s1-prefix.json`, `results/vocabulary-s1-prefix-evaluated.json`, `results/vocabulary-s1-extra-prefixes.json`, `results/vocabulary-s1-extra-prefixes-evaluated.json`.

A JSON whitelist/span validator was added and tested in `Sources/QuibbleCore/VocabularyEdits.swift`. It rejects malformed proposals, unknown targets, protected spans, overlap, and ambiguous repeated source spans. **It does not establish semantic correctness**: an allowed name can still be the wrong name. It is qualification infrastructure and is not connected to ordinary dictation.

## Native Qwen ASR hints

The existing Qwen ASR adapter accepts text context. With all thirteen terms together, it recovered Siobhan but missed several other difficult names; six negative controls were preserved. Supplying one relevant term improved four of the difficult names in this small probe, but Caoimhe still became Kiva. That does not establish a solution for a real dictionary containing many entries.

There were 52 broad-list runs (Cohere/Qwen, 13 clips, twice each) and 12 additional single-hint Qwen runs. Evidence: `results/name-asr/`. Automatically selecting a single word from the desired answer would be an invalid benchmark; no such oracle routing was integrated into the app.

## Repository discoveries and actual decoder probes

[NVIDIA NeMo supports phrase boosting](PARAKEET-VOCABULARY-REPO.md) with a real decoding graph. [Cohere has no documented built-in dictionary option](COHERE-VOCABULARY-REPO.md), but its logits expose a place to test the same family of methods. Both required a reversible benchmark patch to Quibble's pinned Swift adapter.

The probes use the existing installed weights, the pinned NVIDIA graph algorithm, canonical/lowercase SentencePiece paths, no aliases, and no cleanup. They are greedy-decoder experiments, not a full port of NeMo's optimized CUDA/Triton runtime or variable-BPE support. Parakeet preserves acoustic blank decisions and duration selection. Cohere adds the paper's EOS protection heuristic.

Seven Parakeet configurations and six Cohere configurations × 13 audio clips × two runs = **338 native ASR runs**. All repeated outputs agreed. Zero-weight output matched the unmodified baseline for both models on all thirteen clips, twice each.

| Engine | Boost weight | Exact positive sentences / 7 | Positive sentences ignoring only case/final punctuation / 7 | Negative sentences changed / 6 | Median warm ASR, ms |
|---|---:|---:|---:|---:|---:|
| Parakeet | Baseline | 1 | 1 | 0 | 17.83 |
| Parakeet | 0 | 1 | 1 | 0 | 17.91 |
| Parakeet | 0.5 | 1 | 1 | 0 | 17.64 |
| Parakeet | 1 | 2 | 2 | 0 | 17.43 |
| Parakeet | 2 | 3 | 3 | 1 | 17.57 |
| Parakeet | 4 | 4 | 4 | 2 | 17.75 |
| Parakeet | 6 | 3 | 3 | 2 | 17.73 |
| Cohere 4-bit | Baseline | 1 | 1 | 0 | 62.93 |
| Cohere 4-bit | 0 | 1 | 1 | 0 | 62.42 |

| Cohere 4-bit | 2 | 2 | 3 | 0 | 63.74 |
| Cohere 4-bit | 4 | 2 | 5 | 3 | 62.56 |

The punctuation-tolerant column is reported separately to avoid counting a missing full stop as a missed name; it still requires the rest of the sentence to match. It does not excuse damaged surrounding text. Higher weights were exploratory probes, not production settings.

Examples:

- Parakeet weight 2 recovered Niamh and Superwhisper, but also joined ordinary “quick time.”
- Parakeet weight 6 changed the report's article, removed words around Aisling, reduced “Call Kiva after lunch.” to “Caoimhe.”, and changed unrelated Maya to Mae.
- Cohere weight 4 recovered Siobhan, Niamh, Aisling and Superwhisper, often dropping final punctuation; it also changed unrelated Sean to Siobhan.

Added active MLX allocation was 3,080,192 bytes for Parakeet and 5,570,560 bytes for Cohere. This is the device allocation delta, **not total process memory**: Python preparation, decoded Swift tables and JSON buffers are excluded. The dense representation is probe scaffolding. Warm timing differences are within the scale of this small experiment's noise; no speedup claim is warranted. Model load, microphone capture, and insertion are excluded from warm ASR times.

Evidence: `results/native-bias-evaluation.json`, `results/parakeet-bias/`, `results/cohere-bias/`, reversible patches/runners under `competitor-probes/parakeet-bias/` and `competitor-probes/cohere-bias/`. Both dependency/loader patches were restored after measurement. No experimental decoder hook is enabled in the ordinary app.

## Competitor implications

Public competitor evidence supports separating vocabulary guidance from mandatory correction rules. Whisper-style ASR prompts and dictionary-aware generic cleanup prompts are documented/visible in some competitors; an S1 dictionary-prefix-and-strip implementation was not verified. Superwhisper's newer changelog mentions enhanced vocabulary and forced alignment, but does not disclose the full implementation. Wispr Flow's public API accepts dictionary context without revealing its internal model/decoder architecture. See the dated, pinned [competitor report](COMPETITOR-VOCABULARY.md).

## Release gate still open

Before changing default inference: improve preferred-word-only recall without material negative-control regressions, test independent human speech and larger dictionaries, measure full resident memory and release-to-insert latency, verify vocabulary on/off and model switching, then rerun cleanup/insertion integration. Successful unit tests and a clean signed build do not close this quality gate.
